LinkSMM Documentation

Thank you for choosing LinkSMM. This guide explains how to install, customize, and extend the multi-page SMM and digital marketing services marketplace template.

Template scope: LinkSMM is a static front-end template built with semantic HTML, Bootstrap, custom SCSS, and JavaScript. WordPress, WooCommerce, databases, authentication, email delivery, and payment processing are not included.

Installation

  1. Extract the downloaded archive.
  2. Upload the HTML files and the complete assets directory to the same web root.
  3. Use index.html or index-2.html as the homepage.
  4. Replace demo branding, service information, prices, contact details, policies, and images.

Local preview

python3 -m http.server 4173

Open http://localhost:4173/ in a browser. A local server is recommended because some browser behavior may be restricted when HTML files are opened directly from disk.

The template is designed for current versions of Chrome, Firefox, Edge, and Safari. Test your customized content on desktop, tablet, and mobile devices before publishing.

HTML customization

Major page areas use Start/End comments. Keep the existing Bootstrap container, row, and column structure intact when replacing content.

Logo and brand images

LinkSMM uses image logos in the header, mobile navigation, and footer:

  • assets/images/logo.svg — standard logo for light backgrounds.
  • assets/images/logo-white.svg — light logo for dark backgrounds.
  • assets/images/favicon.svg — browser favicon used by every page.

The simplest method is to replace these files while keeping the filenames. When using different dimensions, update the HTML width and height values while preserving the intrinsic aspect ratio.

<!-- Logo on a light background -->
<img src="assets/images/logo.svg" width="190" height="46" alt="Your Brand">

<!-- Logo on a dark background -->
<img src="assets/images/logo-white.svg" width="190" height="46" alt="Your Brand">

Brand checklist: also update page titles, descriptions, logo alternative text, footer copyright, email addresses, physical address, social links, and every visible occurrence of “LinkSMM”.

Headers and menus

Most pages use .linksmm-header. Homepage two adds .linksmm-home-two-header for its alternate desktop appearance. Both versions share the same responsive off-canvas navigation at widths of 1024px and below.

Dropdowns use WordPress-compatible classes and support up to three levels. Keep direct ul > li > a + ul nesting, do not place buttons or wrapper elements inside menu items, and do not add extra classes or IDs to .sub-menu.

<li class="menu-item menu-item-has-children">
    <a href="shop.html">Services</a>
    <ul class="sub-menu">
        <li class="menu-item">
            <a href="product-details.html">Service Details</a>
        </li>
    </ul>
</li>

Header markup is repeated across the static HTML files. After editing navigation, copy the matching header version to every page that uses it. The mobile menu logo, close control, backdrop, and three-level submenu behavior depend on the existing data attributes and class names.

Footer content

All pages use .linksmm-footer. Homepage two also uses .linksmm-home-two-footer for its alternate call-to-action and presentation. Update the correct version without removing its structural classes.

  1. Replace the footer logo and company description.
  2. Update product, company, support, policy, and account links.
  3. Replace demo email, phone, address, and social destinations.
  4. Keep the data-current-year attribute for the automatic copyright year.
<footer class="linksmm-footer">
    <a class="linksmm-logo linksmm-footer-logo" href="index.html">
        <img src="assets/images/logo-white.svg" width="190" height="46" alt="Your Brand">
    </a>
    <p>Replace this text with a concise business description.</p>
</footer>

Editing content, links, and images

  • Keep existing section and component classes when replacing headings or paragraphs.
  • Use relative links such as about.html for included pages and complete HTTPS URLs for external destinations.
  • Keep descriptive alt text for meaningful images and empty alternative text only for decorative images.
  • Preserve image width and height attributes to reduce layout shift.
  • Use loading="lazy" on below-the-fold images, not the main hero image.
  • Use anchors for navigation and buttons for interactive actions.

WordPress and WooCommerce conversion

The HTML is prepared for later theme development, but it is not a WordPress theme. Navigation uses menu-item, menu-item-has-children, and sub-menu. Product gallery markup also includes familiar WooCommerce classes. During conversion, replace repeated headers, footers, loops, product data, cart data, and forms with WordPress or WooCommerce template functions rather than treating the static examples as backend functionality.

Multi-page update checklist

  1. Choose index.html or index-2.html as the primary homepage.
  2. Update matching headers, menus, footers, logos, and account links across all pages.
  3. Replace service descriptions, prices, testimonials, statistics, contact details, and policies.
  4. Search for LinkSMM, .example, and placeholder destinations before publishing.
  5. Test menus, forms, filters, tabs, accordions, sliders, product gallery, cart controls, and links through a local server.

SCSS, typography, and colors

Edit assets/css/style.scss. Its numbered CSS index matches the section order, while reusable colors, fonts, shadows, and radii are defined near the top under :root.

:root {
    --color-primary: #2563eb;
    --color-primary-hover: #1d4ed8;
    --color-secondary: #6d5dfc;
    --color-accent: #0b1533;
    --color-text: #46536a;
    --color-background: #f7f9fd;
    --color-surface: #ffffff;
    --font-heading: "Manrope", sans-serif;
    --font-body: "Inter", sans-serif;
}

Project-owned SCSS uses pixel values for spacing, typography, dimensions, and breakpoints. Keep that convention when extending the stylesheet.

Compile SCSS

npx sass assets/css/style.scss assets/css/style.css --style=expanded --source-map

Do not edit style.css directly if you plan to compile the SCSS again. Always include the compiled CSS when delivering customized HTML files.

JavaScript features

Project-specific behavior is organized in assets/js/custom.js. It includes:

  • sticky headers and responsive off-canvas navigation;
  • WordPress-style nested mobile submenu controls;
  • header search and Escape-key closing behavior;
  • quantity controls, product gallery switching, and product tabs;
  • blog category filtering and keyword search;
  • FAQ accordions and login/register tabs;
  • Swiper testimonial sliders;
  • demo form status messages, current year, and back-to-top control.

Load order: keep jQuery, Popper, Bootstrap, and Swiper before custom.js. The included vendor files are retained for template components and future customization; update vendor libraries from their official releases instead of editing minified files manually.

Submenu state uses the is-submenu-open class so menu anchors remain compatible with the intended WordPress markup. Interactive buttons retain the state attributes required by their associated controls.

Code validation and quality

All 21 customer-facing HTML pages were checked with the W3C Nu HTML Checker. After any content or structural edit, validate the affected pages again—especially navigation, forms, tabs, accordions, labels, and unique IDs.

  • Validate HTML at validator.w3.org/nu.
  • Preserve the existing heading hierarchy and semantic landmark elements.
  • Keep each id unique and every control relationship valid.
  • Run a JavaScript syntax check after editing custom.js.
  • Compile SCSS and test affected pages above and below the 1024px navigation breakpoint.
node --check assets/js/custom.js
npx sass assets/css/style.scss assets/css/style.css --style=expanded --source-map

Forms and commerce

LinkSMM is a static HTML template. Contact, custom quote, comment, coupon, login, registration, cart, checkout, dashboard, and order-confirmation screens are front-end demonstrations and do not send data or process orders.

Demo forms marked with data-demo-form prevent normal submission and show an example status message. Replace that behavior when connecting a PHP handler, API, CRM, WordPress form plugin, or another backend.

Cart quantities and product options are interface examples only. Use WooCommerce or another secure commerce platform for product data, sessions, taxes, order storage, authentication, and payment. Never collect real payment credentials without a suitable PCI-compliant provider.

Images

Logos, hero graphics, service images, blog images, and placeholders are stored in assets/images. Replace an image while keeping its filename to preserve all references, or update each related HTML src and SCSS url().

  • assets/images/products contains service thumbnails.
  • assets/images/blog contains article thumbnails.
  • assets/images/placeholders contains redistribution-safe placeholder graphics.

Product and blog cards use a 1200 × 750 source ratio. Keep a similar ratio to preserve the intended card layout.

Preview assets: AI-generated preview imagery is demonstration content. Follow the included licensing notes and replace preview-only images with properly licensed or supplied placeholder assets before redistribution or production use.
